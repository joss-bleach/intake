# Open Food Facts (and comparable databases): UK coverage, generic-food gaps, and fallback prior art

Research date: 2026-08-09

## Summary

- Open Food Facts (OFF) is a large, fast-growing, crowdsourced database — roughly 4 million products globally across 180+ countries as of the 2025/2026 press page ([world.openfoodfacts.org/press](https://world.openfoodfacts.org/press)) — but it is overwhelmingly a **branded/packaged product** database, not a generic-food database.
- UK-specific product counts found via search (not independently re-verified against a live, successfully-fetched country page — see caveat below) range from ~134,000 to ~172,000 products, a small fraction (roughly 3–4%) of OFF's global total, consistent with OFF's origin as a French project that expanded internationally over time.
- OFF's own documentation states plainly that data is "provided voluntarily by users" with "no assurances that the data is accurate, complete, or reliable" ([openfoodfacts.github.io API docs](https://openfoodfacts.github.io/openfoodfacts-server/api/)).
- A secondary analysis (Nutrola blog, commercial/non-primary source) reports only ~67% of OFF entries have complete macronutrient data (energy/protein/carbs/fat) and fewer than 20% have micronutrient data beyond sodium — flagged here as **unverified against an OFF primary source**, since the OFF wiki's own "Data quality stats" page was inaccessible (blocked by an anti-bot "Anubis" challenge) during this research.
- OFF does not meaningfully cover **generic/homemade foods** ("1 banana", "cooked white rice") — this is corroborated directly by real-world open-source app maintainers/users (Waistline GitHub issues), not just inference.
- **USDA FoodData Central (FDC)** is the standard generic-food fallback in the open-source tooling ecosystem: it provides Foundation Foods (lab-analyzed minimally-processed foods) and SR Legacy (historical Standard Reference generic foods) via a free, CC0-licensed REST API ([fdc.nal.usda.gov/api-guide](https://fdc.nal.usda.gov/api-guide/)), though it is acknowledged to be US-centric with regional/international foods underrepresented.
- The **UK's CoFID** (Composition of Foods Integrated Dataset, published by Public Health England / OHID) is the UK-specific analogue to USDA SR Legacy/Foundation Foods — a curated, lab-analyzed generic-food composition table released as an Excel spreadsheet under the Open Government Licence v3.0, updated roughly every 2–4 years (2015, 2019, 2021) ([gov.uk CoFID page](https://www.gov.uk/government/publications/composition-of-foods-integrated-dataset-cofid)). It has no public REST API — it is a static spreadsheet + PDF user guide.
- The dominant open-source fallback pattern, seen concretely in two real, actively maintained projects (Waistline and OpenNutriTracker), is: **query OFF first for barcode/branded lookups → if no hit (or for generic-food search), query USDA FDC (and/or other national datasets) as a secondary source** — with USDA data typically labeled distinctly in the UI so users know it's a different provenance than the branded scan data.

## Open Food Facts UK Branded Product Coverage

- OFF's global press page states the database contains "around 4,000,000 products" spanning "more than 180 countries," with "30+ countries have more than 10,000 products, 8 more than 100,000" ([world.openfoodfacts.org/press](https://world.openfoodfacts.org/press)).
- Web search results (not independently confirmed by a successful direct page fetch — OFF's country/facet pages returned HTTP 503 or an Anubis bot-check page during this research) indicate a UK product count in the range of **~134,081 to ~172,232 products**, depending on which mirror/date was indexed (`world.openfoodfacts.org/facets/countries/united-kingdom`, `uk.openfoodfacts.org/product-count`). **This figure should be treated as approximate/unverified** — I was not able to load these pages directly to confirm the exact live number; only third-party search-result snippets referenced it.
- Historically, OFF's UK presence grew from **200 products (mid-August 2014) to 1,200 products (November 2014)** during a dedicated "Food Open Data Creation Weekend" UK push, per an OFF blog post dated **December 4, 2014** ([blog.openfoodfacts.org/?p=19](https://blog.openfoodfacts.org/?p=19)). That post also describes UK-specific integrations at the time: "Made Near Me UK" (combining OFF data with FSA approval numbers and OpenStreetMap) and ingestion of Food Standards Agency (FSA) open data (European Approval Numbers, FSA Hygiene Ratings) to auto-identify manufacturers. This shows UK coverage started from a very small base and required dedicated community effort — it was not native to the founding (French) dataset.
- Given OFF's ~4,000,000 global total, a UK count in the 130k–170k range represents roughly **3–4% of the global database**, disproportionate to the size of the UK grocery market, though not unusually small compared to other non-founding countries.

## Open Food Facts Generic Food Coverage

- OFF's data model and contribution workflow (photographing a barcode, a nutrition-facts panel, and a labeled package) is built around **packaged/branded retail products with a barcode**. This is confirmed by OFF's own API tutorial and the described contribution flow ([openfoodfacts.github.io API docs](https://openfoodfacts.github.io/openfoodfacts-server/api/)), which centers entirely on barcode-identified products (GTIN-based lookups).
- Direct, real-world corroboration of the generic-food gap comes from the Waistline open-source calorie tracker's GitHub issue tracker:
  - Issue **"Support generic foods, such as fruit" (davidhealey/waistline #222)**: a user reports that Open Food Facts "only stores branded products," making it impossible to look up fresh fruit like a banana; a commenter proposes USDA FoodData Central as the fix, citing concrete values for "100g of Banana" (~89 kcal, 1.9g protein, 2.6g fiber) ([github.com/davidhealey/waistline/issues/222](https://github.com/davidhealey/waistline/issues/222)). The issue was closed as a duplicate of the broader USDA-integration request.
  - Waistline's own FAQ documentation states outright: OFF "only stores branded products," and recommends enabling USDA FoodData Central integration because "it contains many generic and non-branded foods that cannot be found on Open Food Facts" ([github.com/davidhealey/waistline/blob/master/FAQ.md](https://github.com/davidhealey/waistline/blob/master/FAQ.md)).
- This is strong, primary (project-maintainer-authored) evidence that generic/homemade food coverage in OFF is a known, acknowledged gap in the open-source nutrition-tracking community, not a hypothesis.

## Data Quality Issues

- OFF's own API documentation and developer docs state: "Data in the Open Food Facts database is provided voluntarily by users... there are no assurances that the data is accurate, complete, or reliable" ([openfoodfacts.github.io/openfoodfacts-server/api/](https://openfoodfacts.github.io/openfoodfacts-server/api/)).
- OFF maintains a "Data quality stats" wiki page and a live dashboard (referenced at `mirabelle.openfoodfacts.org/off-stats/data_quality_stats` per search-result snippets), but **I was unable to load `wiki.openfoodfacts.org/Data_quality_stats` directly** — it returned an "Anubis" bot-protection block page rather than content, so its specific completeness metrics could not be verified against the primary source in this session.
- A secondary source (Nutrola, a commercial nutrition-app vendor's blog comparing databases) claims only **~67% of OFF entries have complete macronutrient data** (energy, protein, carbs, fat) and **fewer than 20% have micronutrient data beyond sodium** ([nutrola.app blog](https://nutrola.app/en/blog/open-nutrition-datasets-compared-usda-openfoodfacts-nutrola)). **This is an unverified secondary claim** — Nutrola is not a neutral or primary source (it's marketing its own competing dataset), and I could not cross-check the figure against OFF's own data-quality dashboard due to the access block above. Treat this number as indicative only, not authoritative.
- The Wikipedia article on Open Food Facts corroborates the general crowdsourcing model and reliance on volunteer accuracy but does not itself quantify error/completeness rates ([en.wikipedia.org/wiki/Open_Food_Facts](https://en.wikipedia.org/wiki/Open_Food_Facts)).
- Known structural sources of inconsistency (from OFF's own contribution guidance, as summarized in search-result snippets from the wiki, not independently loaded in full): entries are expected to be filled in strictly from what's visible on the physical package photo, and contributors are told not to estimate/fill in values absent from the label — meaning many products legitimately have partial nutrition tables rather than fabricated complete ones. This is consistent with (but does not itself prove) the reported ~67% macronutrient-completeness figure above.

## Comparable Databases (USDA FDC, UK CoFID)

**USDA FoodData Central**
- Provides four data types via one API: **Foundation Foods** (lab-analyzed, minimally processed foods — cited elsewhere as ~2,300 foods, via the Nutrola secondary source, unverified against FDC's own page), **SR Legacy** (historical Standard Reference generic foods), **Survey Foods / FNDDS** (2019–2020 dietary-study foods), and **Branded Foods** (manufacturer-submitted branded products) ([fdc.nal.usda.gov/api-guide/](https://fdc.nal.usda.gov/api-guide/)).
- REST API with four endpoints (`/food/{fdcId}`, `/foods`, `/foods/list`, `/foods/search`), free with a data.gov API key, rate-limited to 1,000 requests/hour/IP (30/hr and 50/day on the shared demo key) ([fdc.nal.usda.gov/api-guide/](https://fdc.nal.usda.gov/api-guide/)).
- **License: public domain, CC0 1.0 Universal** — no attribution restrictions beyond a suggested citation ("U.S. Department of Agriculture, Agricultural Research Service. FoodData Central, 2019.") ([fdc.nal.usda.gov/api-guide/](https://fdc.nal.usda.gov/api-guide/)).
- Widely reported (secondary source, Nutrola blog, unverified against FDC directly) as **US-centric**, with international dishes, regional products, and non-US food systems underrepresented — a relevant caveat for a UK-focused app relying on it for generic-food fallback (e.g., UK-specific dishes/products won't be well represented, though basic ingredients like "banana" or "white rice" are universal enough to be covered).

**UK CoFID (Composition of Foods Integrated Dataset)**
- **Publisher: Public Health England** (now part of the Office for Health Improvement and Disparities, OHID) ([gov.uk CoFID page](https://www.gov.uk/government/publications/composition-of-foods-integrated-dataset-cofid)).
- **License: Open Government Licence v3.0** ([gov.uk CoFID page](https://www.gov.uk/government/publications/composition-of-foods-integrated-dataset-cofid)).
- **Format: static files only** — an Excel spreadsheet (main dataset, ~4.42 MB), a separate Excel file for "old foods," and a 37-page PDF user guide (~759 KB). **No REST API** was found or referenced on the gov.uk page.
- **Update cadence:** roughly every 2–4 years — versions in 2015, 2019, and 2021; the 2021 update added data from a 2020 nutrient-analysis report on pork cuts and corrections to specific items (e.g., watercress vitamin C, soya yogurt iodine) ([gov.uk CoFID page](https://www.gov.uk/government/publications/composition-of-foods-integrated-dataset-cofid)).
- The gov.uk page itself did not state a total food-item count for CoFID — this figure was not found in this research session and should be looked up directly in the spreadsheet if needed for the decision ticket.
- CoFID is the direct UK analogue of USDA's Foundation Foods/SR Legacy: a small, curated, lab-verified generic-food composition table (traditionally known as "McCance and Widdowson's Composition of Foods") rather than a live, crowdsourced, barcode-driven database. It is well suited as an authoritative UK generic-food fallback, but integrating it requires building your own API/lookup layer around the spreadsheet since none is provided.

## UK-Specific Gaps

- OFF started with essentially no UK data (200 products in August 2014) and required a dedicated community/hackathon push to reach even 1,200 products by the end of that year ([blog.openfoodfacts.org/?p=19](https://blog.openfoodfacts.org/?p=19)) — indicating the UK was never a founding market for OFF (a French-founded project) and its UK coverage is a product of subsequent, uneven volunteer effort rather than systematic build-out.
- Current UK product counts (approximately 130,000–170,000, per unverified search snippets since direct page loads were blocked/unavailable during this session) represent a small fraction of OFF's ~4 million global total and are almost certainly incomplete relative to the actual number of UK supermarket SKUs (UK supermarkets alone stock tens of thousands of SKUs per major chain, with total UK grocery SKUs across all retailers likely well into six figures or more before considering variants/pack sizes).
- I could not locate a dedicated, current Open Food Facts forum thread or blog post specifically auditing UK coverage gaps in this session (the forum's specific threads were not directly loaded — `forum.openfoodfacts.org` appeared only as a general search hit, not fetched); this is a gap in this research that a follow-up session could close by searching the OFF forum directly for terms like "UK coverage," "Tesco," "Sainsbury's," "Aldi UK."
- No UK-specific fallback pattern (e.g., integrating CoFID or FSA data as a secondary source) was found among the open-source apps surveyed — Waistline and OpenNutriTracker both use USDA FDC as their non-OFF fallback, not any UK-specific dataset, despite Waistline's FAQ acknowledging that "it is unlikely that support for more online databases will be added anytime soon" ([github.com/davidhealey/waistline/blob/master/FAQ.md](https://github.com/davidhealey/waistline/blob/master/FAQ.md)). This suggests CoFID integration would be novel/differentiating work rather than something to copy from existing prior art.

## Existing Fallback Patterns / Prior Art

**Waistline** (github.com/davidhealey/waistline, GPLv3, Cordova/Framework7 Android app)
- Primary source: Open Food Facts, configurable by language/country under Settings > Integration.
- Documented fallback: "Waistline falls back to USDA Branded if no Open Food Facts hit," and separately recommends enabling USDA FoodData Central specifically because OFF lacks generic/non-branded foods ([FAQ.md](https://github.com/davidhealey/waistline/blob/master/FAQ.md)).
- Additional fallback for anything neither database covers: a manual bulk "Import Foods" feature (Settings > Import/Export) that loads a local, user-maintained UTF-8 text file of custom food entries — this is effectively the escape hatch for UK-specific or regional foods missing from both OFF and USDA ([FAQ.md](https://github.com/davidhealey/waistline/blob/master/FAQ.md)).
- Concrete user-reported gap driving this design: GitHub issue #222, "Support generic foods, such as fruit" ([github.com/davidhealey/waistline/issues/222](https://github.com/davidhealey/waistline/issues/222)).

**OpenNutriTracker** (github.com/simonoppowa/OpenNutriTracker)
- Combines Open Food Facts with a **multi-source reference backend** (hosted in Supabase) covering USDA FoodData Central (CC0) and the German Bundeslebensmittelschlüssel/BLS (CC BY 4.0, © Max Rubner-Institut), with Anuvaad INDB (India, CC BY 4.0) and TBCA Brazil prepared as future sources — evidence of a pattern that generalizes to per-country generic-food datasets (BLS in Germany plays the same role CoFID would play in the UK).
- Architectural pattern: **backend-first, pre-ingested datasets** — "those datasets are ingested into the Supabase backend ahead of time, so a search reaches that backend and stops there," rather than the client calling multiple upstream APIs live. This centralizes normalization across heterogeneous source schemas and reduces per-request external API exposure.
- User-facing control: a Settings > Food databases screen lets users choose which datasets a search covers, rather than a fixed hidden fallback order.
- This is the closest direct prior-art model for a UK app wanting to add CoFID: **pre-ingest CoFID's spreadsheet into your own backend as a "generic UK foods" source, alongside OFF for branded/barcode lookups**, mirroring how OpenNutriTracker pre-ingested BLS for German generic foods.

**General pattern observed across both projects**
1. Barcode/product-name search hits Open Food Facts first (it's free, has no API key requirement for basic lookups, and covers branded goods well).
2. If no match (or for inherently generic/unbranded items), fall back to a national or USDA generic-food composition dataset, ingested/normalized ahead of time rather than queried live in some designs (OpenNutriTracker) or queried live via a user-configured API key in others (Waistline).
3. Provide a manual/local entry mechanism as the final fallback for anything neither source covers — necessary because even combining OFF + USDA/BLS does not achieve full coverage for every regional or homemade food.
